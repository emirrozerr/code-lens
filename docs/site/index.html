CodeLens

CodeLens is a code-intelligence layer for AI agents. It parses Java and Python codebases into a Neo4j knowledge graph and exposes that graph — through an MCP server, a REST API, and a web UI — so AI agents and humans can query structural context (callers, callees, domains) instead of relying on text search alone.

The Three Tiers

CodeLens is structured around three cooperating tiers, each with a distinct role.

Python Backend src/codelens/

CLI, Tree-sitter AST parsers, Neo4j client, MCP server, clustering, and a FastAPI auth + admin REST layer.

Next.js Frontend frontend/

Admin panel and demo UI: streaming chat at /ask, a force-directed graph at /graph, and admin CRUD under /admin/*.

Neo4j

The graph database that stores the code knowledge graph (nodes, relationships, and discovered domains). Runs via Docker.

Components

Frontend — Next.js

App Router with React 19, Tailwind v4, shadcn/ui, TanStack Query. Route groups: (auth) /login, (demo) /ask + /graph, (admin) /admin/*. middleware.ts gates routes by decoding the codelens_token JWT cookie.

REST API — FastAPI

22 endpoints across auth, users, repos, jobs, domains, stats, graph, and chat. JWT auth via httpOnly cookie; admin-only routes guarded by a role dependency. Streams chat and job status over SSE.

MCP Server — FastMCP

Exposes 7 read-only tools (search_nodes, get_code_context, get_callers, get_callees, get_domains, get_domain, get_domain_content) over stdio or SSE. Each tool runs a Cypher query and returns plain text.

Indexer — Tree-sitter

Walks a repo, dispatches .java/.py files to language parsers, emits CodeNode/CodeEdge objects, and resolves call targets by name. Supports full and incremental indexing.

Clustering — Louvain + Groq

Loads the graph into NetworkX, runs Louvain community detection (python-louvain), and asks Groq to name and summarise each community as a Domain.

Watcher — watchdog

A daemon that watches the repo for file changes, debounces them, re-parses only affected files, and syncs the delta into Neo4j.

CLI — Click

Commands: index (in-memory), ingest (parse + load Neo4j), watch (incremental daemon), mcp (start MCP server), api (start FastAPI).

Neo4j 5

Community edition with APOC + GDS plugins. Stores File/Class/Function/etc. nodes, calls/contains/imports/etc. relationships, and Domain nodes with IN_DOMAIN edges.

Deployment Topology

The project ships a docker-compose.yml that brings up the full stack. Each service maps to a distinct process; only Neo4j and the API start by default.

Service Image / Command Ports Notes
neo4j neo4j:5-community 7474 (Browser), 7687 (Bolt) APOC + GDS plugins
api build: . → codelens api --host 0.0.0.0 --port 8000 8000 FastAPI REST; uses bolt://neo4j:7687 internally
mcp-server codelens mcp --transport sse --port 8001 8001 Commented out in docker-compose.yml; run on demand
frontend Next.js dev/build 3000 Run separately with pnpm dev
By default docker compose up -d starts only Neo4j and the FastAPI API. The MCP server is started on demand (stdio for local AI clients, or SSE for remote).
